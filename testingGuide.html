Phase 1 of 7

Infrastructure Health Check

Verify Docker services are up and all endpoints are reachable before testing anything else.

1
Start all Docker services
Terminal ▶
Run in your project root
docker-compose -f docker-compose.yml -f docker-compose.monitoring.yml up -d
Then verify all containers are running
docker-compose ps
Expected — all containers show "Up"
jobque-api Up 0.0.0.0:3000->3000/tcp jobque-worker Up 0.0.0.0:3001->3001/tcp jobque-redis Up 0.0.0.0:6379->6379/tcp jobque-postgres Up 0.0.0.0:5432->5432/tcp jobque-prometheus Up 0.0.0.0:9090->9090/tcp jobque-grafana Up 0.0.0.0:3002->3000/tcp jobque-alertmanager Up 0.0.0.0:9093->9093/tcp
⚠ If any container shows "Exit" — run: docker-compose logs <container-name> to see the error.
2
Check Prometheus targets
Browser ▶
GET http://localhost:9090/targets
What you should see in the browser
jobque-api State: UP Last scrape: <1s ago jobque-worker State: UP Last scrape: <1s ago prometheus State: UP Last scrape: <1s ago
⚠ If you see State: DOWN — your NestJS app is not exposing /metrics or Prometheus cannot reach it. Check that REDIS_HOST and PORT env vars are set correctly in docker-compose.
3
Verify /metrics health endpoint
GET ▶
GET http://localhost:3000/metrics/health

{ "status": "healthy", "timestamp": "2026-04-01T10:00:00.000Z", "uptime_seconds": 42, "memory_mb": 87, "pid": 1, "node_version": "v20.11.0" }
4
Verify Grafana is running
Browser ▶
URL http://localhost:3002
Login credentials
Username: admin Password: jobque2024

1
Register (creates tenant + admin user)
POST ▶
POST http://localhost:3000/auth/register

private readonly SCALE_UP_THRESHOLD = 1; // was 500 private readonly MIN_COOLDOWN_MS = 5_000; // was 30_000 private readonly POLL_INTERVAL_MS = 3_000; // was 10_000 private readonly MAX_WORKERS = 5; // cap low for test

Phase 7 of 7

Alert Rules Verification

Trigger alert conditions manually and confirm Alertmanager receives them.

1
Check Alertmanager is running
Browser ▶
URL http://localhost:9093

You should see the Alertmanager UI with an "Alerts" tab. It should show "0 alert groups" when everything is healthy.

2
Check alert rules in Prometheus
Browser ▶
URL http://localhost:9090/alerts
  • HighJobFailureRate — State: Inactive (no failures yet)
  • DLQDepthHigh — State: Inactive
  • WorkerHeartbeatMissing — State: Inactive
  • NoWorkersForQueue — State: Inactive
  • QueueDepthHigh — State: Inactive
  • APIHighErrorRate — State: Inactive

"Inactive" means the condition is not met. "Pending" means it's in the for: window. "Firing" means Alertmanager has been notified.

3
Trigger the DLQ alert manually
Watch ▶

Submit a job with failTest: true metadata to trigger failures and DLQ movement:

{ "jobType": "image_resize", "priorityLevel": "HIGH", "metadata": { "failTest": true, "fileUrl": "https://example.com/test.jpg", "format": "png", "width": 100, "height": 100 } }
Expected in logs after all retries exhausted
[BaseWorker] Job failed x | attempt 3/3 [BaseWorker] Job x moved to DLQ [BaseProcessor] Job x permanently failed

Then check Prometheus — jobque_dlq_depth and jobque_jobs_failed_total should increment. If DLQ exceeds 10 and stays there for 5 minutes, the DLQDepthHigh alert fires in Alertmanager.

5
Final Prometheus query checklist
Browser ▶

Run each of these in http://localhost:9090/graph and confirm they return data:

  • rate(jobque_jobs_completed_total[5m]) — shows completions per sec
  • histogram_quantile(0.95, rate(jobque_job_duration_seconds_bucket[5m])) — p95 latency
  • jobque_worker_memory_mb — worker RSS in MB
  • jobque_worker_cpu_percent — CPU percentage
  • time() - jobque_worker_heartbeat_timestamp — should be < 30
  • jobque_tenant_cap_hit_total — cap hit count
  • jobque_autoscaler_scale_up_total — scale events
  • rate(jobque_http_requests_total[5m]) — HTTP request rate
  • jobque_band_promotions_total — band promotions (after 60s wait)
  • jobque_nodejs_heap_size_used_bytes — Node.js heap
